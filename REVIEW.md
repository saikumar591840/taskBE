# REVIEW.md

Review of the starter `app/main.py`. All items below are fixed in my version.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Builds shift start with `punch_in.replace(...)` in whatever time zone the datetime has (naive/server-local, not IST). The late test is `minutes > 10` on already-floored minutes, so a 09:40:30 punch (10 min 30 s after a 09:30 start) floors to 10 and is wrongly treated as on time (R2: strictly more than 10:00 is late, and must report 10); seconds not truncated; no overnight shifts. | Server in UTC, punch 09:45 IST -> shift start computed on the UTC date/time. Overnight shift 22:00 punching 02:00. | `shift_bounds()` builds IST-aware start/end for the attendance date; `late_minutes_for()` compares seconds (> 600) and floors. |
| 2 | `compute_work_hours` | `round()` is banker's rounding on floats (R4 wants half-up); no truncation to whole seconds. | 4.495h-type values, e.g. 16182 s should give 4.50. | `Decimal` with `ROUND_HALF_UP`; inputs truncated at the boundary. |
| 3 | `compute_overtime` | Uses the *same* calendar day for shift end (wrong for overnight); no 30-minute minimum (R3); mixes an aware IST datetime with a possibly naive punch_out -> `TypeError`. | Overnight 22:00-06:00 shift gives negative/zero overtime; 5 minutes after shift end returns 5 instead of 0. | `overtime_minutes_for()` uses `shift_bounds()` and returns 0 below 30. |
| 4 | `create_employee` | Check-then-insert race (two parallel creates both pass the `find_one`). No unique index. No input validation (emp_code format, email, `HH:MM`, `joined_on`, `shift_start == shift_end`). `created_at` is naive local time and is returned as a datetime, not epoch ms. | Fire two identical POSTs in parallel -> two 201. POST `{"joined_on":"2026-02-30"}` -> stored. | Unique index on `emp_code`, catch `DuplicateKeyError` -> 409. Pydantic patterns/validators -> 422. `created_at` stored in UTC, returned as ms. |
| 5 | `list_employees` | `skip = page * page_size` skips the first page (should be `(page-1)`). `total` counts the whole collection, not the filter. No sort (R: by emp_code). No bounds on page/page_size. | `page=1` returns the 2nd page; `department=X` total is wrong; `page_size=100000`. | Correct skip, `count_documents(q)`, `sort emp_code`, `Query(ge=1, le=100)`. |
| 6 | `punch_in` - employee lookup | `emp` can be `None` -> `TypeError` -> 500 for an unknown employee (should be 404). | POST unknown `emp_code`. | `get_employee_or_404`. |
| 7 | `punch_in` - time handling | `datetime.fromtimestamp(ms/1000)` uses the *server's* local zone and returns naive datetimes; `if body.punched_at` treats a value of 0 as "missing"; no seconds truncation; no range check (seconds, floats, strings accepted); date taken from local time, not IST / overnight rule (R1). | Server in UTC: 23:30 UTC punch (05:00 IST next day) gets the wrong date. Send `punched_at: 1783312500` (seconds). | `ms_to_dt()` (UTC, truncated), `StrictInt` + range, `attendance_date()` with the IST/overnight rule. |
| 8 | `punch_in` - race | Check-then-insert: two simultaneous punch-ins both pass `find_one`, giving two records for the same day. | Parallel requests. | Unique index on `(emp_code, date)`; `insert_one` and catch `DuplicateKeyError` -> 409. |
| 9 | `punch_in` - status | `status` is a free string: `ABSENT`, `LEAVE` or garbage can be created via punch-in. | POST `{"status":"ABSENT"}`. | `Literal["PRESENT","WFH","ON_DUTY"]`. |
| 10 | `punch_in` - response | Leaks internal `_id` as `id`; returns datetimes instead of epoch ms; contract says no ids. | Inspect response. | `record_out()` serializer (ms, no id, defaults for legacy fields). |
| 11 | `list_attendance` | Loads the entire matching collection into memory, sorts in Python, slices in Python. Sort lacks the `emp_code` tie-breaker. `total = len(docs)`. | 100k docs -> slow, big memory. `page=0` gives a negative slice. | Query with `sort`, `skip`, `limit` in MongoDB, `count_documents`; compound indexes for the sort. |
| 12 | `list_attendance` - input | `date_from > date_to` not rejected; dates and status not validated; page/page_size unbounded; `_id` leaked; datetimes not converted to ms. | `date_from=2026-07-10&date_to=2026-07-01` returns empty 200. | `DateStr` validator, `Literal` status, 422 for reversed range, `record_out()`. |
| 13 | `/health` | Always returns ok even when MongoDB is down (contract: 503). | Stop MongoDB, call `/health`. | `ping`; 503 on failure. A global handler also turns driver errors into 503, not 500. |
| 14 | Mongo client | Default PyMongo returns naive datetimes; mixing with aware values raises `TypeError`. No server selection timeout. No indexes at all. | Any subtraction of naive/aware datetimes. | `MongoClient(tz_aware=True, tzinfo=UTC)`, timeout, `ensure_indexes()` in lifespan. |

## Looked at and decided it was fine
* Handlers are plain `def`, so FastAPI runs them in a thread pool; blocking PyMongo calls do not block the event loop. No need for Motor.
* `load_dotenv()` does not override variables already set in the environment, which matches the contract ("real environment variables must win").
* `doc.pop("_id")` after `insert_one`: correct for removing the id the driver adds (but I replaced it with a serializer).
